# Codex：山の画像生成で再発させないこと

2026-09-06、ユーザーの「学習して次回から起こらないようにシステム化」の依頼に基づく記録。Claude用の指示・スキルには転記しない。

## 確認された原因と対処

- 画像完成後も停止ボタンが残り、保存前の待機が続いた。停止ボタンだけを完了判定の唯一の根拠にしない。
- 対応する要求文が完全一致し、画像ロード済み・画像の編集/共有操作が表示された状態が20秒安定したら、同じ会話を再読み込みする。停止状態が解消した後に同じ完成結果を保存し、要求を再送しない。途中画像や別の要求文はこの経路で保存しない。
- アクセス制限の「了解」を、待機時間が終わるまで押さない不具合があった。既知の制限通知は発見時に閉じる。待機中も確認する。通知を閉じる操作は送信再試行と分ける。
- 「数分待つ」のアクセス制限では3分待って再試行する。表示された具体的な解除時刻やログイン要求は尊重する。別モデル/APIで制限を回避しない。
- 回収工程終了を全素材完成として扱わない。未完了枠を生成工程へ自動で渡す。再起動前に保存済み画像の照合記録を取り込み、重複生成を防ぐ。

## 報告と完成判定

- プロセス生存・定期更新だけで「順調に動いている」と報告しない。照合済み数、最終保存時刻、現在の画像、再試行/制限表示を確認する。保存数が増えていなければ明示する。
- 「了解を押した」「再開した」は、その時点の画面・動作を確認してから報告する。ユーザーが先に押した場合は、こちらが押したと扱わない。
- PNG数だけで完成を判断しない。要求文、SHA、デコード、縦横比、キャラ透過を検査する。全枠の自動検査終了と内容の最終目視確認は分ける。

## 実装と回帰テスト

`Yama_Story/System_Tools/imagegen/` の `driver.js`、`run.py`、`recovery_service.py`、`integrity.py` が実装。
`test_driver_completion.js` は停止ボタン残留・途中画像除外・正常完了、`test_generation_limit.py` は待機中の了解と再送抑止、`test_recovery_service.py` は異常復旧と回収→生成移行を検証する。
次回の変更時は対象の回帰テストを実行し、稼働中のページへ新しいドライバが反映されたことと、実ファイル保存まで確認する。

## 制限の判定・報告（同日追加）

- 「しばらくお待ち」「少々お待ち」「思考中」「問題が発生しました」は生成上限の根拠にしない。同じ表示が2回出ても上限へ昇格させない。
- ユーザーの要求文・サイドバーの履歴タイトル・過去ログは、現在の制限の根拠に使わない。現在の会話本文（要求文を除く）と通知の明示的な制限文だけを使う。
- 画像生成の利用枠とアクセス頻度制限を区別する。判定には表示文、表示場所、観測時刻を添える。
- 待機中でも現在の制限表示がなければ「再試行待ち・現在の制限表示は未確認」。システムの再試行予定を、サービスの解除時刻として報告しない。
- 回帰テストは `test_limit_evidence.js` と `test_limit_reporting.py`。実際の画面表示がないのに「生成上限」と報告する挙動を再導入しない。
