**やること**

1. 二重起動を防ぐため、先に `pgrep -f run.py` で確認し、動いていれば `pkill -f run.py` で止める
2. 作業フォルダで、次を実行して裏で走らせる
   ```
   nohup python3 run.py "<作品フォルダ>" > /tmp/yama_imagegen.log 2>&1 &
   ```
3. 3分ほど待ち、`/tmp/yama_imagegen.log` と、作品フォルダの `images/` の枚数を見て、
   動き出したことを確認する
4. 確認できたら、その時点の枚数（`ls -1 images/*.png | wc -l`）を報告して終わってよい

**とても大事なこと**

- **画像生成には1日あたりの上限があります（ChatGPT Plusで約90枚）。**
  上限に当たったら止まりますが、**これは故障ではありません。**
  `run.py` が解除までの残り時間を読み取り、待って、**空いた瞬間に自分で再開します。**
  リセットは毎晩22時ごろです。
- **上限に当たっているのを見ても、直そうとしないでください。**
  スクリプトを書き換えたり、別の生成手段に切り替えたりする必要はありません。
  待つのが正しい動作です。
- **`run.py` を二重に起動しないでください。**同じアカウントの枠を食い合って無駄になります。
- 全部で312枚あり、**数日かかります。**途中で終わっても失敗ではありません。

**進み具合の見かた**

`images/` に入っている画像の枚数が、そのまま進捗です。
どこまで進んだかは画像そのものが覚えているので、途中で止まっても続きから再開できます。

## 補足（人が読む用・Codexに貼らなくてよい）

### 上限が解けたら自動で動く仕組み

`driver.js` の中に入っている。上限に当たると、ChatGPTの返答に出る
「あと何分で解除か」を読み取り、その残り時間に応じて投げ直す間隔を変える。

| 解除までの残り | 次に投げるまで |
|:--|:--|
| 10時間 | 20分後 |
| 1時間 | 15分後 |
| 20分 | 5分後 |
| 8分 | 2分後 |

遠いうちは間隔を空けて無駄打ちを減らし、**近づくほど詰める**。
解除の直前は2分間隔なので、実質「空いた瞬間」に走り出す。
表示された時刻が外れて早く空いた場合でも、**最長20分で気づく**。

書かれた解除時刻を信じて寝かせる作りにしていないのは、この保険のため。

### 二重に走らせない理由

上限はアカウントに付いている。`run.py` を2つ動かしても枚数は増えず、
上限に当たるのが早くなるだけ。**必ず1つだけにする。**
