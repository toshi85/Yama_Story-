## フリーズ・中断への対策

- 一度に220件や大量の画像をモデルへ読み込ませない。**5〜10カット単位**で原寸確認・記録・保存を終え、次のバッチへ進む。各バッチの終了時にASSET番号、入力SHA、判定、修正ファイル、次の番号をJSONに書く。再開時はそのJSONと実ファイルを照合し、完了分を重複生成しない。
- 画像生成も**1件試作→合成確認→小バッチ**。通信失敗時は理由をログに残し、原因に応じた復旧を1回だけ試す。同じエラーを再送・別モデル・別経路で反復しない。受付IDが残った生成を二重発注しない。
- 長いローカル処理は `.codex/automation/README.md` の方式でログ・終了コード・出力SHAを保存する。開始やPIDの存在だけで「進行中」「完了」と報告しない。長時間無応答なら直前に保存したバッチから再開する。AIの判断がフリーズ後に自動継続すると約束しない。
- 進捗は `確認済み / 不適合 / 未判定 / 編集者待ち / 修正済み / 納品済み` の件数で短く伝える。推測の完了率や未検収の合格数を出さない。
