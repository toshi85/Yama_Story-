# Yama 引用フレーズは一次資料で原典確認必須

## 学習元事案（2026-05-25）

星野道夫台本作成時:
- 競合動画 `1lGLCHSapVI` で言及されていた **直子さん「あのクマを許せないと思ったことはない」** 発言を、エージェントBレポート経由で台本§22に引用した
- ユーザー指摘後、原典を直接WebFetchで確認した結果:
  - 1101.com（ほぼ日刊イトイ新聞 星野道夫特集）には**該当発言の記載なし**
  - 新潮社『星野道夫と見た風景』書籍紹介ページにも**該当発言の記載なし**
  - WebSearchでも該当発言の原典は確認できず
  - 結局 **1lGLCHSapVI 競合動画のみが言及しており、原典不明**
- リサーチ品質低下を回避するため、当該発言を§22から **削除** した

## ルール（強制）

### Rule 1: 引用フレーズは「一次資料」のみ採用

| 採用OK | 採用NG |
|---|---|
| 本人の著書・エッセイ・公式インタビュー | 競合動画・ゆっくり解説・まとめサイト |
| 公的機関・報道機関の一次取材記事 | 個人ブログの孫引き |
| 学術論文・公式報告書 | 二次資料の二次引用 |
| 本人発信SNS・公式サイト | 口承・伝聞のみの発言 |

### Rule 2: 「諸説あり」の婉曲化

原典確認できない発言・諸説ある事実は、以下のように婉曲化:

| 状況 | 表現 |
|---|---|
| 原典確認済み | 「『XXX』と語っています」「『XXX』と書いています」（直接引用） |
| 諸説あり・一説 | 「XXXと伝えられています」「XXXとされる説もあります」 |
| 原典確認不可・出所不明 | **書かない**（リスク高い） |

### Rule 3: 引用には必ず `<!-- src: -->` で原典明記

```markdown
ナレーター: 「自然はいつも、強さの裏に脆さを秘めています」<!-- src: 星野道夫『旅をする木』文藝春秋 1994 p.XX -->
```

- 書籍引用: タイトル・出版社・刊行年・可能ならページ番号
- Webサイト引用: 媒体名・記事タイトル・URL・取得日
- 動画引用（避けるべき）: 競合動画引用は原則禁止。どうしても使う場合は「XXX氏の発言として伝えられる」と婉曲化

### Rule 4: 完了前チェックで全引用の原典確認

台本完成前に以下を実施:
1. `grep -nE '「.+」' Master.md` で引用箇所を抽出
2. 各引用の前後に `<!-- src: -->` があるか確認
3. ないものは原典探索 or 削除

### Rule 5: 競合動画の発言を孫引きしない

- 競合動画の音声・字幕に登場する発言を、自チャンネル台本に直接引用するのは禁止
- 競合動画は自チャンネル同様、二次資料（自社編集を経た情報）であり、一次資料ではない
- 競合動画で見つけた発言は、必ず一次資料（書籍・公式報道）まで遡って原典確認する

## 実装上の手順

### 台本執筆中
1. 引用フレーズを書く前に「これは一次資料で確認済みか？」を自問
2. 確認できていない引用は **書かない**
3. どうしても書きたい場合は「と伝えられています」「と語っていたとされます」と婉曲化

### 完了報告前
1. `grep -nE '「.+」|"[^"]+"' Master.md` で全引用抽出
2. 各引用に `<!-- src: -->` が前後にあるか確認
3. ない引用は原典探索 → 確認できなければ削除 or 婉曲化
4. validator/hook で機械チェック

## 検証

- 新規 hook `validate-yama-quote-source.sh` で引用箇所に `<!-- src: -->` の不在を検出
- Yama_Story 関連タスク完了報告前に強制実行

**Why:** 出所不明の引用を台本に入れると、視聴者への信頼性が低下し、デマ・フェイク情報拡散のリスクがある。星野道夫事件で「直子さん発言」を孫引きで台本に入れたのは典型的な失敗例
**How to apply:** リサーチ着手時にセットで `feedback_yama_research_direct_webfetch.md` を必ず参照
